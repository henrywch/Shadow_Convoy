Local maximality during growth is the optimization that makes the rest viable. The naive enumerator emits a pattern at every recursion depth ≥ k — millions of redundant prefixes of their own extensions. The local rule fixes this in one line: if any extension preserves the full current membership, the longer route strictly dominates this stack — skip emission.

Emitting only when the recursion either shrinks membership or terminates cuts raw patterns by 10–100× before the global maximality filter even runs. Combined with an inverted-index dominance check (candidates restricted to patterns containing every member of B, seeded on B's rarest plate), what was an O(N²) post-process at 2.6 M patterns becomes a few seconds on tens of thousands.

02 / Where it stands

Implementation complete. Validation pending.

Every stage is built, tested on synthetic fixtures, and wired into the same Slurm + Spark cluster scripts that ran FP-Growth. Four failure modes were encountered and retired along the way (driver result-size cap, OOM from over-permissive Apriori prefilter, executor module-not-found, O(N²) maximality filter). The remaining work is parameter tuning on real data — matching --min-observations to FP-Growth's min_count=50 so the surviving plate set is comparable to the 783-plate FP-Growth result, then promoting day-1 to 31 days.

Status: pipeline functional through cluster materialization on day-1 data (199,949 plates / 3.5 M visits / 293 k ε-clusters in ~40 s of Spark time); driver-side enumeration being re-tuned for FP-Growth-equivalent thresholds. Full-month run is the next milestone.
