# 面向卡口 ANPR 数据的多视角同行车辆挖掘与下游应用

**摘要**　卡口车牌识别（ANPR）数据记录了海量车辆在城市相机网络中的时空轨迹，从中挖掘"结伴同行"的车辆群体，对刑侦研判、套牌稽查与交通流分析具有重要价值。本文以 31 天、约 2.76 亿条卡口记录为对象，提出并实现了三种相互独立的同行检测器：基于 FP-Growth 的格点共现检测、基于 MaxGrowth 的有向路径协同检测、以及基于序列自编码器的轨迹嵌入聚类检测。三者从"格点—路径—向量"三种不同的度量空间刻画"同行"，因而互为补充。在此之上，本文构建了跨检测器的共识融合登记表，将三套车队标注归并为统一、去重、可置信排序的结果；并进一步开发了种子车伴随查询、套牌车（impossible-travel）检测、无 GPS 的相机转移图与 node2vec 嵌入、走廊与 OD 流分析等下游任务。实验表明：单一检测器的"超级连接点"（如出现在 1,548 个车队中的公交/出租）会被融合自动过滤——它们未被其余两个度量空间认可；最终 1,167 个融合组中有 19 个获得三检测器一致认可。全部下游产物均在真实全量数据上完成验证。

**关键词**　大数据；频繁模式挖掘；轨迹表示学习；同行车辆；套牌检测；图嵌入

**项目资源**　代码仓库：[github.com/henrywch/Shadow_Convoy](https://github.com/henrywch/Shadow_Convoy)；在线 Demo：[henrywch.github.io/Shadow_Convoy/Demo](https://henrywch.github.io/Shadow_Convoy/Demo/)。

## I 研究背景和意义

城市卡口相机以"电子围栏"的方式持续记录过往车辆，每一次抓拍产生一条 `(车牌, 相机, 时间戳)` 记录。当这些记录在月级时间尺度上累积到亿级规模时，其中蕴含的并非单车轨迹，而是车辆之间的**协同结构**：哪些车长期结伴而行、沿同一走廊成队移动、或在异常时刻同步出现。识别这些群体是情报主导警务（intelligence-led policing）的核心能力，可用于发现尾随运钞车的可疑车辆、锁定已知目标的同伙、识别被暴露的盯梢车辆等。

然而从亿级稀疏抓拍中可靠地恢复同行群体并不容易。其根本困难在于"同行"本身没有唯一定义：两辆车可以"在同一相机同一时刻反复出现"、可以"沿同一条有向路径连续协同通过多个相机"、也可以"具有形状相似的整体轨迹"。不同定义对应不同算法、发现不同群体、也各有失效模式。因此，单一方法给出的 Top-K 结果往往掺杂大量假阳性（如被所有人"伴随"的公交、出租）。本文的意义在于：用三种度量空间彼此独立地刻画"同行"，再以跨方法一致性作为强证据，从而把三件研究原型沉淀为一个可被实际查询的产品。

## II 研究目标和研究内容

本项目的总目标是：在不依赖任何相机 GPS 坐标的前提下，从 31 天卡口数据中稳健地挖掘同行车辆群体，并支撑可落地的刑侦/稽查下游应用。围绕该目标，研究内容分为三个层次。

第一层是**三种同行检测器**。FP-Growth 把每个"`(相机, 5 分钟桶)`格点"视为一次事务，挖掘频繁车牌项集；MaxGrowth（平台 platoon 模式挖掘）要求群体沿长度 ≥3 的有向相机路径协同通过、且每站到达时间差在 ε 内；轨迹嵌入则用去噪序列自编码器把每辆车的路径编码为 256 维向量，再聚类并以原始共现确认。第二层是**跨检测器共识融合**：将三套车队标注归并为统一、去重、按置信度排序的登记表。第三层是**下游任务**：种子车伴随查询、套牌车检测、相机转移图与 node2vec 嵌入、走廊与 OD 流分析。

## III 相关工作（同类研究进展）

**共现与群体模式挖掘**　频繁项集挖掘以 Apriori[1]与 FP-Growth[2]为代表，后者通过 FP-树避免候选生成，适合大规模事务库。面向轨迹的群体模式则发展出 convoy[4]、swarm[5]、platoon 等定义，近年的综述与分布式流式方法[6]系统梳理了 flock/convoy/swarm 家族；从视频直接挖掘共动模式的工作[7]进一步拓展了数据源。本文的 FP-Growth 与 MaxGrowth 分别落在"无序共现"与"有向协同"两端。

**轨迹表示学习**　t2vec[11]首次用去噪 seq2seq 学习轨迹相似度的鲁棒嵌入；此后表示学习成为轨迹挖掘的主线，VeTraSS[14]面向车辆轨迹相似检索，UniTE[15]统一了时空轨迹预训练流程，最新综述[16]展望了轨迹基础模型。本文的嵌入检测器沿 t2vec 思路，并将"相似轨迹"与"真实共现"解耦确认。

**图嵌入与社区发现**　DeepWalk[8]与 node2vec[9]以随机游走学习节点嵌入，Qiu 等[10]证明其等价于隐式矩阵分解（NetMF），这为无 GPS 的相机图嵌入提供了无需额外依赖的实现路径；Louvain[12]与 Leiden[13]则是大规模加权图社区发现的标准工具。本文用前者恢复相机空间布局，用后者把检测器输出投影为车队。

**ANPR 应用与套牌检测**　基于 ANPR 的车队/伴随分析在刑侦领域已有实践[17]；稀疏 ALPR 轨迹重建[18]是近年热点；套牌车检测的核心是"impossible travel"——同一车牌在过短时间内出现于过远的两地[21][22]。本文将该思想与相机转移图的最短通行时间结合，给出无坐标的实现。

## IV 研究方法

### 4.1 数据集

**数据获取**　原始数据为某城市 31 天卡口抓拍，共 **275,893,209** 条记录，字段为 `(车牌ID, 相机ID, 时间戳)`，相机为 0…976 的整数编号，**不含经纬度坐标**。数据以 CSV 形式存储（约 6.2 GB），并另提供单日、单周两个切片用于快速验证。

**数据勘探与预处理**　勘探发现：曾出现的车牌约 2200 万个，但绝大多数从不结伴；个别"卡死"相机在单个 ε 窗口内可堆积上万车牌（最极端一例达 23,595 个），属读数伪影，需在挖掘前以密度上限剔除。预处理按各检测器需要进行：对 FP-Growth，按 `桶 = ⌊t/300⌋` 分桶并施加 `density_cap=2000`；对 MaxGrowth 与嵌入，先做车牌侧预过滤（按最少观测数、最少访问相机数筛选并取 Top-N），再构建按时间排序的轨迹序列。

**数据存储**　中间产物分层存放：轨迹序列以 Snappy-Parquet 列式存储；车辆嵌入以 256 维稠密矩阵（3,830,566×256）与对齐的车牌索引存储；各下游任务产物按任务分目录落地（详见项目代码仓库）。数据勘探中发现两个嵌入目录因训练失败整体为 NaN，已甄别并保留规范可用的嵌入矩阵；相关脚本加入了非有限行剔除与全 NaN 拒绝逻辑，提升了流水线鲁棒性。

### 4.2 分析算法

**算法一：FP-Growth 格点共现（算法思想）**　把"`(相机, 5 分钟桶)`格点"作为事务、格点内车牌集合作为项集，用 Spark MLlib 的 FP-Growth 挖掘出现次数 ≥ `min_count` 的频繁车牌项集；为避免一组车在桶边界被切开，采用 0 与 ε/2 双偏移网格。其强项是小群体的高精度，弱点是大车队的 C(N,k) 组合爆炸。

```
算法 1  FP-Growth 同行车队挖掘
输入: 抓拍表 R(plate,cam,t); 窗口 ε=300; 最小支持 min_count=50; 密度上限 D=2000
输出: 频繁车牌项集 (plates,k,count)
1  for 偏移 o in {0, ε/2} do
2      给每条记录加列 bucket ← ⌊(t-o)/ε⌋
3      T_o ← R 按 (cam,bucket) 分组, 聚合 collect_set(plate)
4      T_o ← 过滤掉 |交易| > D 的格点          # 剔除卡死相机伪影
5  T ← T_0 ∪ T_{ε/2}
6  F ← FPGrowth(T, minSupport=min_count/|T|)   # Spark MLlib
7  return {(itemset, |itemset|, freq) : itemset∈F, |itemset|≥2}
```

**算法二：MaxGrowth 有向路径协同（算法思想）**　一个平台模式 ⟨O,P⟩ 要求车牌集合 O 中的每辆车都按相同顺序通过有向相机路径 P、每站到达时间差 ≤ ε、相邻两站间跳过的相机数 ≤ d，并取**极大**模式（不被更大的模式包含）。相比 FP-Growth 的无序共现，"协同通过 ≥3 个相机的有向路径"是更强的群体证据。

```
算法 2  MaxGrowth 平台模式挖掘 (要点)
输入: 轨迹 {plate→[(t,cam)…]}; 最小群体 m=2; 最小路径 k=3; 跳变 d=1; 窗口 ε
输出: 极大平台模式 (route, n_cameras, members, n_plates)
1  车牌预过滤: 删除观测<10 或 访问相机<k 的车牌, 取 Top-N
2  对每个候选起点相机 c: 用 ε 把同时到达的车牌聚为根群体
3  路径增长: 沿 d-后继逐步延长 P, 同步收缩成员 O (都须满足 ε 与 d)
4  极大性过滤: 删除被其它模式以 d-子序列方式支配者
5  return 全部满足 |O|≥m 且 |P|≥k 的极大模式
```

**算法三：轨迹嵌入聚类（算法思想）**　用去噪 GRU 序列自编码器把每辆车的 `(相机,时间)` 序列编码为 256 维向量（训练时随机丢弃部分观测以增强对漏检的鲁棒性），在向量空间聚类得到候选车队，再回到原始数据，仅保留成员"确有共现"（同相机 ε 窗口内多次同现）的簇——以此把"路径相似"与"真正结伴"区分开。**关键在于嵌入是车牌级的**：嵌入矩阵与车牌索引严格行对齐，每辆车对应唯一一个 256 维向量，故聚类、确认与下游 ANN 检索均可精确到单车。GPU 上用 cuML 聚类，无 GPU 时回退 scikit-learn。

```
算法 3  轨迹嵌入聚类 + 共现确认 (要点)
输入: 轨迹 {plate→[(t,cam)…]}; 嵌入维 D=256; 丢弃率 ρ; 最小簇 mc; 窗口 ε; 确认阈 W
输出: 已确认车队 (cluster_id, members, confirmed)
1  序列化: 每辆车按时间排序 → 相机序列 s_p = [cam_1,…,cam_n]
2  训练去噪 GRU 自编码器:
3      重复: 随机丢弃 s_p 的 ρ 比例相机 → ŝ_p             # 模拟漏检, 提升鲁棒性
4           最小化 重构 decoder(encoder(ŝ_p)) 与 s_p 的损失
5  编码: 每辆车 v_p ← encoder(s_p) ∈ R^D                  # 车牌级向量, 共 3.83M 个
6  聚类: labels ← cluster(L2norm({v_p}), HDBSCAN/KMeans)  # cuML(GPU)/sklearn(CPU)
7  共现确认: for 每个候选簇 C:
8      w_C ← #{(相机, ε-窗口) : C 内 ≥2 辆车在此同现}
9      confirmed[C] ← (w_C ≥ W)                           # 区分"路径相似"与"真正结伴"
10 return {(C, members(C), confirmed[C]) : |C| ≥ mc}
```

**算法四：共识融合（算法思想）**　把三套车队标注视为对每辆车的三个标签，**按标签元组分组**即可得到"被 ≥2 个检测器共同分到一组"的共识块（无需物化两两边）：按完整三元组分组得 3-of-3，按各二元对分组得 2-of-3；保留 ≥2 车的块并按成员集去重。置信分 `score = 一致检测器数 + 各检测器原生强度的对数-归一化均值`，使"一致性"主导、原生强度（共现次数/路径权重/嵌入共现窗口）破平。

**算法五：套牌检测（impossible-travel，算法思想）**　无 GPS 坐标，故以相机转移图（边权=学习到的中位通行时间）的**全对最短通行时间** SP(i,j) 充当"距离"。对一辆车按时间排序的相邻抓拍 (cam_i,t_i)→(cam_j,t_j)，若 `Δt < SP(i,j)·tol`（路途过快）或图上很远却在极短时间出现（瞬移），即判定不可能；按不可能次数排序并以 `min_hits` 设阈，单次可能为时间戳噪声。相机嵌入用 node2vec 的等价矩阵分解实现：加权随机游走→窗口共现→PPMI→截断 SVD，仅依赖 polars 与 sklearn。

## V 实验结果及分析

**三检测器各自结果**　FP-Growth 在 `min_count=50` 下得到 **5,447** 个车队、仅涉及 **783** 个车牌（占曾见车牌的 0.0036%），表明本数据的同行信号极其稀疏；其中 `{16970573,16972992,18150551,3271142,3542309,511670}` 构成稳定的 6 车永久车队，其 4 车恒同子集恰好出现在 1,548 个车队中（≈ 50/天）。MaxGrowth 得到 **223,184** 个模式、覆盖 **87,047** 个车牌，路径长度随相机数骤减、绝大多数集中于 3 相机，最繁忙走廊 `434→404→238` 由 9,296 辆车经过。嵌入检测器在 31 天全量上得到 **12,709** 个簇、其中 **4,041** 个经共现确认，**覆盖 102,779 个车牌**（68,122 个落入已确认簇）——与 MaxGrowth 的 87,047 同量级，而远超 FP-Growth 的 783。三种方法的核心结果汇总于图2。一个关键观察是：FP-Growth 的超级连接点（`3271142` 等）与 MaxGrowth 的超级连接点（`490759` 等）几乎不相交，且后者集中度低得多（最高 172 个模式 vs 1,548），印证了三度量空间"按构造彼此分歧"。

**融合结果与分析**　把三套车队（含 MaxGrowth 图社区得到的 396 个路径证据车队）融合后，得到 **1,167** 个组，其中 **19** 个获三检测器一致认可、1,148 个为二者一致（图5）；最强的一组是 51 车的 3-of-3 群体。最具说服力的结果是**验证假设被数据推翻**：原本预期会"三检一致登顶"的超级连接点集合 `{3271142,16972992,…}` 根本未进入登记表——它们不在任何嵌入车队、也几乎不在路径车队中。这说明它们只是 FP-Growth 在单一度量空间下的共现伪影（公交/出租），融合**自动将其过滤**。这正是跨检测器一致性优于任何单检测器 Top-K 的最清晰例证。

## VII 总结和不足

**总结**　本文以亿级卡口数据为对象，实现了"格点—路径—向量"三种互补的同行检测器，并以跨检测器共识融合把三件原型沉淀为统一、可查询、可置信排序的登记表；在其上完成了种子车查询、套牌检测、无 GPS 相机图与 node2vec、走廊/OD 流分析等下游任务。核心结论是：单检测器的高频假阳性（公交/出租超级连接点）会被多空间一致性自动过滤，融合显著提升了结果的可解释性与可信度；同时，相机转移图独立复现了路径检测器的走廊，多条证据相互印证。全部下游产物均在真实全量数据上运行验证。

**不足与改进**　其一，套牌检测对"同址相机对"（如 `785→786`，图上无直达边导致最短路高估）存在假阳性，应在边表中加入观测最小通行时间或合并同址相机。其二，融合采用精确标签元组分组，对标注边界敏感，后续可引入 Jaccard 重叠匹配与时间维（首末出现、活跃天数）。其三，嵌入 ANN 与 UMAP 仅在 GPU 节点完成全量，CPU 仅在切片验证。其四，本数据缺乏地面真值，候选仍需人工研判；车辆角色分类（公交/出租 vs 私家）可进一步提精度。
